# #514 — One JSON-response parser for the five LLM prompt sites; make the distill malformed outcome countable

**Scope note (corpus adjudication):** Preserve the five-site matrix and malformed-distill observability. **Parser salvage must be explicit per caller** — each site keeps its own fallback semantics; only strip+loads(+salvage) consolidates. **No provider capability flag** unless needed only as a measured follow-up. **Structured outputs remain out of slice.**

**Defect (one sentence):** five call sites each hand-roll a *different* markdown-fence stripper + `json.loads` over LLM output (one of them buggy), and on the one site that feeds the nightly capture loop a malformed judge response is folded into "judged, nothing worthy" — the session is watermarked away and no counter can ever see it.

## The change

### A. One seam: `src/trellis/llm/json_response.py` (new)

**Preserve current semantics exactly.** The shared module implements fence strip + `json.loads` only. **Only enrichment** adds object salvage (existing regex `\{.*\}` DOTALL); distill, miner, reconcile, and extract stay **strict** after fence removal — no preamble salvage, no shared `{`..`}` recovery. Extract keeps its existing `{`..`}` + bare-list lift in `_parse_json_with_exception` **after** a strict parse returns `MALFORMED` (site-local, not a shared salvage mode).

```python

    EMPTY = "empty"           # valid JSON whose shape means "nothing" (e.g. [])
    MALFORMED = "malformed"   # fence+loads could not recover
```

**Site adapters** (each replaces strip+loads only; shape validation and fallbacks stay local):

| Site | adapter | post-parse (unchanged) |
|---|---|---|
| `extract/llm.py` | `parse_json_response` → if `MALFORMED`, apply existing `{`..`}` recovery + list lift in `_parse_json_with_exception`; else map `VALUE` | `(None, exc)` / raise `ExtractionFailureError` |
| `mcp/reconcile.py` | `parse_json_response` → strict | `MALFORMED` → `_fallback_outcome(model_id,"malformed_response")`; `VALUE` dict → existing field validation |
| `session_capture/distill.py` | `parse_json_response` → strict | `VALUE`+list → candidates; `EMPTY` → `[]`; `MALFORMED` → see B |
| `learning/miner.py` | `parse_json_response` → strict | `MALFORMED` → `EXTRACTION_FAILED` + raise; `VALUE`+list → precedents |
| `enrichment/service.py` | `parse_json_response` → on `MALFORMED`, existing regex `\{.*\}` DOTALL salvage **in adapter**; else strict path | `EnrichmentResult(success=False)` on final failure |

**Enrichment-only object salvage** stays in `_parse_response`, not in `parse_json_response` — the seam does not widen any other site.

### B. Distill malformed outcome — typed throughout, no sentinels

`parse_candidates(raw, session_id) -> JSONParseResult` (never `list | None`).

`distill_session` returns `JSONParseResult` (never `list | None`):
- Upstream judge unreachable (no client, timeout, transport, prompt-too-large) → synthesize `JSONParseResult(outcome=...)` with a dedicated upstream flag **or** keep transport failures as a separate early return that `capture.py` maps to `sessions_judge_unavailable` — but **malformed parse must not reuse that path**.
- Model responded → forward `parse_candidates` result unchanged.

`capture.py:322-330` adapter (the only place outcomes become counters/watermarks):

```python
match distill_result.outcome:
    case JSONParseOutcome.MALFORMED:
        report.sessions_judge_malformed += 1
        log warning "distill_response_malformed"
        # fall through to empty-candidates watermark (unchanged)
    case JSONParseOutcome.EMPTY:
        ...  # judged, nothing worthy
    case JSONParseOutcome.VALUE:
        ...  # candidates from validated list
# judge-unavailable is detected before parse (transport/timeout/None client), not via MALFORMED
```

Add `sessions_judge_malformed: int = 0` to `CaptureReport`, `to_payload`, and `ops/capture_coverage.py` funnel notes.

## Non-goals (say so in the PR)

- **Structured outputs / `response_schema` on `LLMClient`:** provider matrix is OpenAI json_object vs Ollama `format` vs Anthropic tool-use; defer until the malformed rate is measured (the issue's own ordering). No capability flag in this slice unless a follow-up PR is opened after measurement.
- Retrying a malformed distill (leaving the session un-watermarked): at `temperature=0.0` a retry likely reproduces the same output and would pin the session forever; the semantic call (retry vs count) is an owner question only if the measured count is non-trivial.
- Changing any site's post-parse validation or fallback event vocabulary.
- Touching `providers/*` (#517 just did).

# #514 — One JSON-response parser for the five LLM prompt sites; make the distill malformed outcome countable

**Scope note (corpus adjudication):** Preserve the five-site matrix and malformed-distill observability. **Parser salvage must be explicit per caller** — each site keeps its own fallback semantics; only strip+loads(+salvage) consolidates. **No provider capability flag** unless needed only as a measured follow-up. **Structured outputs remain out of slice.**

**Defect (one sentence):** five call sites each hand-roll a *different* markdown-fence stripper + `json.loads` over LLM output (one of them buggy), and on the one site that feeds the nightly capture loop a malformed judge response is folded into "judged, nothing worthy" — the session is watermarked away and no counter can ever see it.

## The change

### A. One seam: `src/trellis/llm/json_response.py` (new; `trellis` is a dependency of both worker packages)

```python

    VALUE = "value"              # parsed JSON present; caller validates shape
    EMPTY = "empty"              # valid JSON array/object that means "nothing" (e.g. [])
```

**Per-caller salvage policy (explicit — the seam does not choose):**

| Site | `salvage` | `on_error` | post-parse behaviour (unchanged strictness) |
|---|---|---|---|
| `extract/llm.py` | `True` | `raise` | bare-list lift; `(None, exc)` contract |
| `mcp/reconcile.py` | **`False`** | `result` | **strict** — only a clean fenced/unfenced object parses; preamble salvage is **not** enabled unless issue #514 is separately reopened to widen reconcile acceptance. `MALFORMED` → `_fallback_outcome(..., "malformed_response")`; `VALUE` → existing validation |
| `session_capture/distill.py` | `True` | `result` | `VALUE` + list → candidates; `EMPTY` (`[]`) → `[]`; `MALFORMED` → distinct from empty (see B) |
| `learning/miner.py` | `True` | `raise` | `EXTRACTION_FAILED` + raise |
| `enrichment/service.py` | `True` | `raise` | `EnrichmentResult(success=False)` |

Each caller documents its row; replacing strip+loads is the only consolidation — **fallback semantics stay local**.

### B. Make the distill malformed outcome observable (the capture-loop half)

`parse_candidates` maps `JSONParseResult` → `list[CandidateMemory] | None` using the typed outcomes — **no `None` collision** between malformed and judge-unavailable:

- `outcome == VALUE` and value is a list → candidates (existing validation)
- `outcome == EMPTY` (parsed `[]`) → `[]` ("nothing worthy")
- `outcome == MALFORMED` → return a dedicated sentinel or propagate `JSONParseResult` to `distill_session` (do **not** reuse `None`, which already means judge/transport unavailable upstream)

`distill_session` / `capture.py:322-330`:

```python
if judge_unavailable: report.sessions_judge_unavailable += 1; return
if parse_result.outcome is MALFORMED: report.sessions_judge_malformed += 1; log warning "distill_response_malformed"; fall through to empty-candidates watermark path
if candidates == []: ...
```

Add `sessions_judge_malformed: int = 0` to `CaptureReport` (`models.py:175`), to its `to_payload` dict so it rides `CAPTURE_SWEEP_COMPLETED`, and to `ops/capture_coverage.py`'s funnel + note branches. Docstring: malformed *judge* is not `malformed_lines` (transcript lines).

### C. Derived rule pinning the seam (house standard 4)

`tests/unit/llm/test_json_response_rule.py`: AST-scan `src/` for `Call` nodes whose func is `Attribute(attr="generate")` carrying a `messages=` keyword (helper `generate_call_sites(tree) -> list[(path, lineno)]` added to `tests/ast_rules.py`; #264's plan reuses it). For every module containing one, require the module to reference `parse_json_response` (import-name check via `construction_names`/`calls_to_any`) **or** be listed in `NOT_JSON_SITES` with a reason (today: empty). Guards: `assert_hand_read_floor(found, 5)`; decoy check — `AdvisoryGenerator.generate(days=...)` call sites (`retrieve/advisory_generator.py`, `trellis_api/routes/admin.py:313`, `trellis_cli/analyze.py:1325`, `trellis_cli/worker.py:772`) must NOT be collected (`messages=` keyword is the discriminator, not the attr name); synthetic tree via `assert_scan_is_not_vacuous` containing (a) `await self._llm.generate(messages=m)` (caught), (b) `gen = client.generate; gen(messages=m)` (bound-method evasion — document as a known blind spot rather than claim it is caught, or catch `Name("generate")` calls with `messages=` too), (c) `client.generate(**kw)` (flag as "cannot classify" → fail, the #424 `**kwargs` treatment), (d) a decoy `x.generate(days=3)` (must not be caught), (e) a module with a site and no parser import (must fail the rule).

## Tests (fail before / pass after) and mutants

- `test_strip_code_fence_keeps_last_json_line_when_trailing_fence_missing` — input ` ```json\n[{"a":1},\n{"b":2}] ` (no closing fence). **Fails on old miner logic**; port the same input into `tests/unit/workers/learning/test_miner.py` driving `_parse_candidates` end-to-end (population 2 items, distinct titles/confidences, so a dropped line changes the count).
- `test_parse_json_response_salvages_preamble` (`"Sure! {…}"` and `"Here you go:\n[…]"`) — kills `salvage=False` default mutant and a `find("{")`-only mutant (array case).
- Reconcile: keep existing `TestParseVerdict` malformed params green with `salvage=False` (preamble-wrapped valid verdict still `None` — strictness preserved). Add one case: clean fenced verdict still parses.
- Distill: `test_parse_candidates_malformed_is_distinct_from_empty` — `"not json"` → `MALFORMED` path (not `[]`, not judge-unavailable `None`); `"[]"` → `EMPTY`/`[]`; capture sweep with garbage vs `[]` asserts `sessions_judge_malformed == 1`, both watermarked.
- `capture_coverage` note test: funnel with `sessions_judge_malformed=2` renders the sentence; with 0 it does not (both branches, so a constant sentence fails).
- Rule test: the synthetic-tree cases above; plus the rule fails on a copy of the tree with the parser import removed from one site.
- Mutation targets to report: `strip_code_fence` dropping the "one trailing line" guard; `parse_json_response` swapping `rfind` → `find`; sentinel/None confusion in `distill_session`; `to_payload` key.

Fixture shapes to avoid: single-candidate arrays (a dropped line then reads as "empty", same as malformed); all-identical confidences; a sweep fixture with one session.

## Non-goals (say so in the PR)

- **Structured outputs / `response_schema` on `LLMClient`:** provider matrix is OpenAI json_object vs Ollama `format` vs Anthropic tool-use; defer until the malformed rate is measured (the issue's own ordering). No capability flag in this slice unless a follow-up PR is opened after measurement.
- Retrying a malformed distill (leaving the session un-watermarked): at `temperature=0.0` a retry likely reproduces the same output and would pin the session forever; the semantic call (retry vs count) is an owner question only if the measured count is non-trivial.
- Changing any site's post-parse validation or fallback event vocabulary.
- Touching `providers/*` (#517 just did).

## Risks the gate will probe

- "One seam" claim: reviewer greps for a residual `startswith("```")` — there must be zero in `src/`.
- Salvage on reconcile is **off** by policy; a reviewer grepping for widened reconcile acceptance should find zero preamble cases.
- Docstring of `parse_candidates` must distinguish `EMPTY`, `MALFORMED`, and upstream `JUDGE_UNAVAILABLE` — none may alias to `None` for malformed.
- The rule's import-presence check is weak (a site could import and not call). Say so in the test docstring; the roster in #264 is the stronger per-site recipe test.
- `CaptureReport` is `extra="forbid"`-adjacent? It is a dataclass; check any JSON schema/consumer (`capture_coverage`, UI) that enumerates keys.

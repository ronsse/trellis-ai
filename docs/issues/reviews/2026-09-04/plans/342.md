# #342 — Close the learning promote-loop test: assert the promoted precedent is *served*

**Scope note (corpus adjudication):** The **load-bearing** closure criterion is an ordinary subsequent **`PackBuilder` / `PACK_ASSEMBLED.injected_items[]`** serving assertion. `get_lessons` / `list_precedents` checks in this plan are **supplementary** — they strengthen the read path but do not alone close the issue if the pack-serving half remains unproven. Verdict stays **valid-slice**.

**Defect (one sentence).** `tests/integration/loops/test_learning_promote_loop.py` proves a promotion
*writes* a graph node but never proves the precedent reaches any read surface, so the promote half of
the loop can be green in CI while `get_lessons` shows nothing (the exact half-state `submit_learning_promotion`
already documents as "entity exists but get_lessons won't show it").

- `.github/workflows/live-infra.yml:215-220` runs `tests/integration/loops/` on `pull_request` **and**
  `push`, against Postgres + Neo4j. So the issue's "runs nowhere" framing is stale for the write half.

- Nothing in the trellis-evals repo is needed: every seam is public (REST `POST /packs`, MCP

## The change (one file, ~60 lines)

File: `tests/integration/loops/test_learning_promote_loop.py`.

1. `_promote_via_cli`: add
   `assert result["precedent_event_status"] == "success", result` and
   `assert result["precedent_event_id"], result`; return `(node_id, precedent_event_id)`.
2. New helper `_seed_decoy_precedent(trellis_bin, subprocess_env) -> None` run **before** promotion:
   `run_cli(trellis_bin, ["curate", "promote", "lp:trace:decoy", "--title", "lp decoy", "--description",
   "decoy precedent", "--format", "json"], subprocess_env)` (`src/trellis_cli/curate.py:53-70`: trace path,
   `target_type="trace"`, **no `--domain` option**, so the emitted payload has `domain: None`). Validation is
   schema-only (`mutate/commands.py:135-138` requires just `title`/`description`; no target-existence check),
   so no trace has to exist. This is the population-of-2 with mixed `domain` (`None` vs `_DOMAIN`), so no
   assertion below is satisfiable by "any precedent". If the CLI is inconvenient, MCP `execute_mutation`
   (`mcp/server.py:2987+`) accepts `operation="precedent.promote"` with the same args.
3. New helper `_verify_precedent_served(loop_env, node_id, precedent_event_id, helpful_candidate)` (**supplementary read-path checks**):
   - `await loop_env.mcp.call_tool("get_lessons", {"domain": _DOMAIN})` → text contains the promoted
     title (`helpful_candidate["precedent_name"]` / the `name` the ENTITY_CREATE used; read it from the
     graph node in `_verify_precedent_in_graph` and pass it along) and **does not** contain `"lp decoy"`.
   - `call_tool("get_lessons", {})` (no domain) → contains **both** titles (proves the decoy landed, so the
     next assertion is about the filter and not about an empty log).
   - `call_tool("get_lessons", {"domain": "learning-promote-none"})` → `"No lessons found."`.
   - With `live_registry(...)`: `rows = list_precedents(registry.operational.event_log, domain=_DOMAIN)`;
     `assert [r["entity_id"] for r in rows] == [node_id]` and `rows[0]["event_id"] == precedent_event_id`
     and `rows[0]["payload"]["source_item_id"] == _HELPFUL_DOC_ID`.
4. **Load-bearing:** after promotion, assemble a fourth ordinary REST pack (`POST /packs`) with the same `intent`/`domain` and assert `node_id in [item["item_id"] for item in pack["injected_items"]]` (or equivalent from `PACK_ASSEMBLED` telemetry). This is the issue-closing assertion; do not skip it in favour of `get_lessons` alone.
5. Call order in the test: `_seed_decoy_precedent` → existing steps → `_verify_precedent_in_graph` → `_verify_precedent_served` → pack-serving assertion.
6. Rename the test docstring tail to `… → graph precedent → served in pack`.

- Supplementary `get_lessons` checks must read through the MCP client (same process boundary a user crosses).
- Decoy with `domain=None`: under M2/M4 both rows are undomained, so `get_lessons(domain=_DOMAIN)` returns
  `"No lessons found."` — killed. Under M5 the decoy appears under `_DOMAIN` — killed. Say this in the PR.

  entity_id` (`scoring.py:380-390`); read it back from the node (`node["name"]`) rather than guessing.
- Order dependence: `list_precedents` is desc; the decoy is emitted first, so under M6 the order flips
  but the filtered list is still length 1 — say explicitly that M6 is out of reach of this test.

# #360 — Document and vector writes bypass the governed pipeline

**Scope note (corpus adjudication):** PR1 = structural governed-write rule + narrowed CLAUDE rule. PR2 routes agent-facing writers. **Issue remains open** until every non-backend writer, batched ingest, and metadata migration path satisfies the final governed state. Record: retention metadata-write exception; **no governed document DELETE**; direct-write roster ratchet; **soft vs strict embedding** modes on one handler.

**Defect statement.** CLAUDE.md's hard rule ("All mutations go through the governed pipeline … No direct store writes") is unqualified, but on `origin/main` (f9ff32c) every document-plane and vector-plane write reaches the store directly: none of the 13 handlers in `create_curate_handlers` (src/trellis/mutate/handlers.py:1417) writes a document or vector row, and nothing pins the boundary, so new bypass sites accrue silently and the #337/#338 "tag written after embed is invisible to semantic retrieval" class keeps recurring per site.

## The change — three ordered PRs

### PR1 (S/M) — pin the boundary, narrow the prose to what is true

1. **`tests/unit/test_governed_write_rule.py`** — derived AST rule over `src/`, built on `tests/ast_rules.py` (`iter_modules`, `calls_named`, `assert_hand_read_floor`, `render_evasion_corpus`):
   - A *direct-write site* is any `Call` whose func is `Attribute(attr in {"put","delete"})` on a receiver whose dotted name ends in `document_store`/`doc_store`/`store` **and** any `Attribute(attr in {"upsert","delete","upsert_many"})` on a receiver ending in `vector_store`/`vstore`. Receiver naming is heuristic, so the rule must also match `registry.knowledge.document_store.<m>` / `registry.knowledge.vector_store.<m>` chains and local aliases assigned from those (walk simple `Name = Attribute` assignments in the enclosing function). Record `(module, lineno, kind)`.
   - Exempt by *directory*: `src/trellis/stores/`, `src/trellis/mutate/handlers.py`. Everything else must appear in `GOVERNED_WRITE_EXEMPTIONS: dict[tuple[module, kind], str]` — the roster carries a prose reason per entry (`"bursty; awaits batched emit (T-3)"`, `"metadata-only; mirrors via sync_vector_metadata"`, `"PR2 routes this"`, `"demo fixture"`), keyed on module+kind, **not** line number (lines churn; a roster keyed on lines rots the way #443's did).
   - Assertions: (a) every found site is rostered — **fails on any new site**; (b) every roster entry is still found — a roster entry with no site is a stale exemption and fails (**the ratchet only shrinks**); (c) `assert_hand_read_floor(found, floor=N)` where N is the hand-read count above (document ~18, vector 6); (d) non-vacuity: render a synthetic tree through `render_evasion_corpus` containing an aliased receiver (`ds = registry.knowledge.document_store; ds.put(...)`), a chained receiver, a keyword-only call, and a `getattr(store, "put")(...)` evasion, and assert the predicate finds the first three and *reports* the fourth as unscannable (explicit `EVASIONS` entry) rather than silently missing it; (e) tokenizer cross-check by line number (the #461 pattern): tokenize each module, find `.put(`/`.delete(`/`.upsert(` tokens on identifiers ending in `store`, and assert the AST scan and token scan agree on line sets — a divergence names the line.
   - Hand-read floor: the inventory above; the coder must re-derive it by `git grep -nE '(document_store|doc_store|vector_store)\.(put|delete|upsert)\(' src/` and reconcile before setting N.
2. **CLAUDE.md** hard rule 2 rewritten to what is true: graph, trace, feedback, retention and redaction mutations go through `MutationExecutor`; document and vector rows are written directly at N rostered sites (`tests/unit/test_governed_write_rule.py` is the roster and it only shrinks); T-3 decided they get governed via `evidence.ingest`; a *new* direct write site fails the rule. Also correct "none writes doc/vector" to "none *creates* a document or vector row; **retention writes lifecycle metadata and mirrors it**". Note **no governed document delete exists**.
3. **Tests that fail before / pass after:** the rule file itself (does not exist before). Mutants to kill: drop the receiver-alias walk (synthetic alias case dies); drop directory exemption for `stores/` (floor assertion overshoots — assert exact count, not `>=`); key the roster on line numbers (assertion (b) on a moved site); remove tokenizer cross-check (re-introduce a `getattr` evasion and assert the scan names its line).

### PR2 (M) — one core `EvidenceIngestHandler`; route the agent-facing writers

1. **`src/trellis/mutate/handlers.py`**: `class EvidenceIngestHandler(registry, *, embed: Literal["soft","strict"]="soft", embedding_fn=None)` implementing `handle(command)`; body = the worker handler's body generalised: validate `args["evidence"]` (`content` required; `doc_id` optional → `None` means store-assigned; `metadata` dict; `preserve_updated_at` bool default False; `dedup_by_hash` bool default True — the `ensure_evidence_document` path uses `get_by_hash`), `classify_metadata_on_write`, `document_store.put(...)`, then embed: **`soft`** → `run_embed_on_ingest(registry, doc_id, content, metadata, source=command.requested_by)` (existing fail-soft hook, `retrieve/embed_ingest_hook.py`), **`strict`** → `build_vector_row` + `vector_store.upsert` and raise on failure (the worker's current posture). Return `(doc_id, "stored"|"deduplicated")`.
2. Register in `create_curate_handlers` under `Operation.EVIDENCE_INGEST` (soft mode). **`trellis_workers/trace_embed/handler.py::TraceSummaryIngestHandler` becomes a thin subclass / instantiation with `embed="strict"`, `embedding_fn=…`** — one class, two modes, not two classes. Its existing tests (tests/unit/workers/trace_embed/) are the regression net for the shared body.
3. Route four non-bursty, agent-facing writers through `build_curate_executor(registry).execute(Command(EVIDENCE_INGEST, …))`: `mcp/server.py:1617` and `:1688` (save_memory, both puts), `trellis_api/routes/curate.py:135` (`POST /documents`), `trellis_api/routes/ingest.py:90` (`POST /evidence`), and `mutate/evidence.py::ensure_evidence_document`. Each removal shrinks the PR1 roster (assertion (b) forces the roster edit — that is the point).
4. Idempotency key: `command.idempotency_key = f"evidence.ingest:{sha256(content)}"` at the MCP/REST call sites, so a replayed save is a replay, not a duplicate. The executor already handles that stage.
5. Tests: for each routed surface, a test that asserts a `MUTATION_EXECUTED` event with `operation == "evidence.ingest"` is emitted **and** that a declared `deny` policy on `evidence.ingest` blocks the write (proving Stage 2 now runs where it previously could not). Fixture: two documents with different `requested_by` and one policy scoped to one surface — population 2, mixed. Mutants: register the handler under the wrong operation (route test dies); `embed="strict"` in core (fail-soft test with a raising embedder dies); drop the idempotency key (replay test dies — assert exactly one `MEMORY_STORED`).
6. `tests/unit/test_policy_gate_rule.py` already requires every `MutationExecutor(...)` to pass a gate; the worker's construction is unchanged so it stays green.

## Risks the gate will probe

- **Receiver heuristic false negatives** — a store reached through a name not ending in `store` (e.g. `self._docs.put`). Mitigation: tokenizer cross-check on `.put(`/`.upsert(` regardless of receiver, reporting *unclassified* receivers as a third bucket that must be empty or rostered; the synthetic tree must include one.
- **Double events on save_memory**: `MEMORY_STORED` (emitted by the MCP path, load-bearing for the #461 capture banner) plus `MUTATION_EXECUTED`. Tests asserting exact event counts in `tests/unit/mcp/` will break; the capture-surface roster test (`test_capture_surface_roster.py`) must still see `MEMORY_STORED` from the MCP emitter with its `requested_by`. Keep `MEMORY_STORED` where it is; do not move it into the handler.
- **`execute_mutation` MCP tool now accepts `evidence.ingest`** — that is a new agent-reachable write of arbitrary content. It is governed (Stage 2), but the PR must say so and add a test that it lands `MEMORY_STORED`-less (so the banner does not clear on it) or decide it should.
- **Fail-soft embed in core vs strict in the worker**: a reviewer will ask why the same handler has two failure postures. Answer in the docstring: agent-facing writes must not lose a memory to an embedder outage (#338's authoritative-document-row rule); the worker's contract is "embedded or not done" because `trace_is_embedded` is its idempotency.
- **Roster ratchet direction**: assertion (b) must be *exact* membership both ways; a `<=` on either side is a constant-satisfiable check.

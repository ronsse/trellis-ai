# #256 — Bolt backends (neo4j / arcadedb) out of core: seam-proving first step only

**Scope note (corpus adjudication):** This plan is **PR1 only** — a registry seam toward extraction into the **already-approved** separate `trellis-stores-bolt` distribution ([`adr-plugin-contract.md`](../../../design/adr-plugin-contract.md), issue #256 acceptance criteria). **PR1 cannot close #256.** Package removal and publish-surface changes follow in later PRs after #351 and this seam land.

**Defect statement.** `StoreRegistry._instantiate` (src/trellis/stores/registry.py:887–986) hard-codes backend-name-keyed construction logic for `neo4j` and `arcadedb` (driver sharing, env fallbacks, ensure-database, provenance migration) and imports `trellis.stores.neo4j.base` / `trellis.stores.arcadedb.base` / `bolt_opencypher.base` to do it — so a backend cannot be moved out of the `trellis` package even though the plugin loader already resolves classes by entry point. Making extraction *possible* is CODE; moving packages and publishing the plugin wheel are follow-on PRs.

## The change (one PR, M)

1. **Backend-side preparation hook.** In `src/trellis/stores/base/` (or `plugins/contract.py` if that exists) add a Protocol:
   ```python
   class RegistryPreparable(Protocol):
       @classmethod
       def prepare_registry_params(cls, ctx: RegistryContext, store_type: str, params: dict[str, Any]) -> dict[str, Any]: ...
   ```
   `RegistryContext` is a small frozen object the registry passes: `env` (a read-only mapping), `shared: dict[str, Any]` (the driver cache — today `_bolt_drivers`), `register_closer(callable)`, `emit_warning(msg)`. Nothing backend-specific.
2. **Move the branches onto the classes.** `Neo4jGraphStore.prepare_registry_params` absorbs `_inject_neo4j_driver` + `_parse_bolt_driver_config`; `ArcadeDBGraphStore.prepare_registry_params` absorbs `_inject_arcadedb_driver` + provenance-migration bookkeeping (state moves from `registry._arcadedb_provenance_migrated` into `ctx.shared["arcadedb:provenance_migrated"]`); `ArcadeDBVectorStore.prepare_registry_params` absorbs `_resolve_arcadedb_vector_params`; `Neo4jVectorStore` shares the driver via `ctx.shared`. `_instantiate` becomes: builtin sqlite/local/postgres/pgvector/s3 branches unchanged, then `if hasattr(cls, "prepare_registry_params"): params = cls.prepare_registry_params(ctx, store_type, params)`, then `cls(**params)`. The registry no longer imports any bolt module.
3. **`_EXTRA_FOR_BACKEND`** stays (it is an error-message hint and cheap); note in a comment that it is the last name-keyed reference and is removed with the packages.
4. **Prove the seam with a synthetic plugin in tests**, not by moving the packages: `tests/unit/plugins/test_registry_prepare_hook.py` builds a fake backend class exposing `prepare_registry_params` that (a) reads `ctx.shared`, (b) registers a closer, (c) mutates params; registers it via a monkeypatched entry point (the loader already has fixtures for this in test_loader.py) and asserts `StoreRegistry` instantiates it with the prepared params, shares state between two store types from the same plugin, and calls the closer on `close()`.

## Risks the gate will probe

- `ctx.shared` becomes an untyped bag; a reviewer will ask why not a typed field. Answer: the registry must not know the driver type — that is the whole point — but key the bag by backend module name and document it.
- Provenance migration runs once per cached driver (registry.py:1237); moving that bookkeeping onto the class must keep the "once per driver, not once per store" property — the existing test pins it; make sure the mutant "run per store" dies.
- Does the hook also need `validate()`/fingerprint access (registry.py `validate`, `test_registry_fingerprint.py`)? Check whether fingerprinting reads driver config; if so, the hook must not change what is fingerprinted.

# #264 — MEMORY_OP_JUDGED: one emitter seam, the two missing judged ops, and a derived roster

**Scope note (corpus adjudication):** Missing live LLM-judged paths are **enrichment classification** (`worker enrich`) and **memory extraction** — not CURATION (no model-judged curation operation exists). Keep the derived roster idea. **#514 sequencing is implementation adjacency** (`generate_call_sites` reuse), not a hard issue dependency.

**Defect (one sentence):** three hand-rolled copies of the `MEMORY_OP_JUDGED` emit exist and two LLM-judged operations that *persist* memory items (`worker enrich` classification; memory-path entity extraction) emit nothing, so the training-pair log is silently partial and nothing in the repo can tell which judge sites are covered.

## The change (two ordered PRs)

### PR-A (M): seam + the two missing emitters

1. **`src/trellis/core/memory_op_judged.py`** (new): `emit_memory_op_judged(event_log, *, op_type, source, model_id: str, ...)` — **`model_id` is required**; the helper rejects empty strings. Builds payload, emits, fail-soft with `memory_op_judged_emit_failed` on emit failure only. Refactor the three existing emitters to call it (equivalence proof: existing tests unchanged).

   **Model identity — required at the LLM-judging service boundary, threaded into every judged emit.** No constants, placeholders, or `extractor_used` substitutes on `MemoryOpJudgedPayload`. Deterministic / model-less paths (alias-match, trace rules, reconcile fallback ADD with no parse, discarded distill candidates) **do not call the emitter**.

   Actual configured models on main (f9ff32c):
   - **Reconcile** (`mcp/reconcile.py`): `WriteBehaviourConfig.reconcile_model` (default `"hermes3:8b"`, env `TRELLIS_RECONCILE_MODEL`); resolved per verdict as `response.model or configured_model_id()` — already threaded into `ReconcileOutcome.model_id` and `emit_reconcile_verdict`.
   - **Distill** (`session_capture/distill.py`): `DEFAULT_DISTILL_MODEL = "hermes3:8b"` (env override in sweep); passed as `distill_model_id` to `emit_distillation_judged` — config string, not inferred post-hoc.
   - **Shadow classify** (`classify/shadow.py:233`): explicit `model_id` arg or `classifier_name` fallback — already on the judging path before emit.
   - **Enrichment** (`EnrichmentService`): constructor `model: str | None` today (worker often passes `None`); **`EnrichmentService` must resolve a required `judging_model_id: str` at init** from the explicit `model=` arg or the wired client's default (e.g. `OpenAIClient._default_model`). Thread `response.model or judging_model_id` into `EnrichmentResult.judging_model_id` on every successful `generate`.
   - **Extraction LLM** (`extract/llm.py`): `LLMExtractor._model` constructor arg; `response.model or self._model` on the extraction-failure path — propagate the same resolved string through `ExtractionProvenance.model_id` on LLM-stage results.

   **When an LLM-judged operation completes but model identity cannot be resolved** (`response.model is None` and no configured `judging_model_id`): emit a loud **`EXTRACTION_FAILED`** (or a new `JUDGED_OP_IDENTITY_MISSING` operational event if preferred) with `failure_kind="model_identity_missing"`, log `memory_op_judged_identity_missing`, and **do not emit `MEMORY_OP_JUDGED`**. Test this branch with a fake LLM returning `LLMResponse(model=None)` and no configured default — reachable on enrichment today when `model=None` and the client omits `model` in the response.

2. **CLASSIFICATION on `worker enrich`**: after `apply_derived_metadata` succeeds, call helper with `op_type=CLASSIFICATION`, `source="worker:enrich"`, `decision=result.auto_class or DECISION_UNCLASSIFIED`, `confidence=result.class_confidence if result.class_confidence is not None else 0.0`, `model_id=result.judging_model_id` (required field on `EnrichmentResult` — only set when identity resolved; if missing, take the degradation path above, not emit). Digest = pre-LLM content snapshot (`doc["content"]` at :1620).

3. **EXTRACTION at one seam** — **never infer per-draft LLM judgment from run-level `result.llm_calls`.** On main, `ExtractionResult.llm_calls` is run-scoped (`hybrid._merge` sums stages; a hybrid pass can be `llm_calls > 0` while every persisted entity came from the deterministic stage). `EntityDraft` has no first-class tier field and **this plan does not add persisted `extractor_tier` stamps** — entity-row/property changes are a non-goal.

   **Sidecar-only correlation (no entity-row fallback):**

   1. **`LLMExtractor`**: after `_to_drafts`, build a sidecar `list[LLMJudgedDraftRecord]` **before any hybrid merge** with one row per LLM-origin entity draft:
      `(draft_key=(entity_type, entity_id or name), entity_type, confidence, model_id, input_hash, input_length)`
      where `model_id = response.model or self._model` (required non-empty or omit that row from the sidecar).
   2. **`HybridJSONExtractor._merge`**: carry the sidecar through unchanged (only LLM-stage rows; deterministic drafts never enter it). Do **not** re-derive judged rows from the merged `ExtractionResult`.
   3. **`run_memory_extraction`**: after `execute_batch`, for each successful fresh mint (`entity_id is None` before batch, `cmd_result.status == CommandStatus.SUCCESS`): emit **only if** sidecar correlation is **provable** — the command's `(entity_type, name)` matches exactly one sidecar row **and** that draft key was **not** present in the deterministic stage's entity list for that run (hybrid collision: deterministic wins in `_merge`, so no judged emit for deduped keys). Pre-bound drafts (`entity_id is not None`, e.g. alias-match `CreativeWork` anchor) never emit. Match sidecar → `cmd_result.created_id` by draft key, not batch index.
   4. **If correlation cannot be proven** (missing sidecar row, ambiguous key match, missing `model_id`): emit loud degradation (`EXTRACTION_FAILED` / `model_identity_missing` or `judged_op_correlation_failed`) and **skip** `MEMORY_OP_JUDGED` — never infer from persisted entity properties or run-level flags.

   **Mixed hybrid fixture (kills run-level-flag mutant):** `HybridJSONExtractor(AliasMatchExtractor, LLMExtractor(fake))` on input where alias-match emits deterministic `Person "Alice"` and the fake LLM returns `Organization "Acme"` + `Person "Bob"`. `result.llm_calls == 1` but batch creates three entities → **exactly two** `MEMORY_OP_JUDGED` (Acme, Bob), **zero** for Alice. Mutant: `if result.llm_calls > 0: emit for every SUCCESS` → test dies (3 events).

### PR-B (S–M): the derived roster

`tests/unit/test_judged_op_roster.py`. Scan `src/` for `.generate(messages=...)` call sites with `generate_call_sites` (from #514's plan; add it to `tests/ast_rules.py` here if #514 has not landed). Hand-read floor: **5** (`extract/llm.py:145`, `mcp/reconcile.py:278`, `trellis_workers/learning/miner.py:173`, `trellis_workers/enrichment/service.py:192`, `trellis_workers/session_capture/distill.py:278`) via `assert_hand_read_floor`. Roster keyed by module → either `NOT_A_MEMORY_OP(reason)` (miner: "persists no memory item; PRECEDENT_PROMOTED only") or a list of `EMITS(op_type, consumer_recipe)` — **a module may have several consumers** (enrichment → shadow pass *and* `worker._run_batch_enrichment`). Each recipe is *run*, against `tmp_path` SQLite stores and an `AsyncMock` LLM, and must produce ≥1 `MEMORY_OP_JUDGED` with the expected `op_type`, a `subject_ref.ref_id` that resolves in the store it names (doc in DocumentStore / entity in GraphStore — this is the join target and the assertion that makes "training example" mean something), and a `model_id` equal to what the fake `LLMResponse.model` reported (kills "constant model id"). Recipes: (a) `run_memory_extraction` with mixed hybrid fixture above → two EXTRACTION events, not three; (b) `worker._run_batch_enrichment` with two candidates, one success one failure → exactly one event; (c) shadow pass → existing; (d) `capture_session`/sweep with a fake distiller → DISTILLATION; (e) reconcile via `emit_reconcile_verdict(run_reconcile(fake))` → RECONCILIATION, plus the fallback case producing **zero** (pinned as intended). Vacuity: `assert_scan_is_not_vacuous` on a synthetic tree (caught: `await self._llm.generate(messages=m)`; rejected-as-unclassifiable: `client.generate(**kw)`; decoy not caught: `x.generate(days=3)`, i.e. `AdvisoryGenerator`); a self-check that monkeypatching `emit_memory_op_judged` to a no-op makes every EMITS recipe fail (the roster can tell an emitter from its absence); rostered module set == scanned module set exactly (a stale roster fails both ways).

## Tests (fail before / pass after) and mutants

- `worker enrich`: two-candidate sweep (one success, one failure; distinct `auto_class`/`class_confidence`) → exactly one event, decision/confidence/model_id from the successful one; **fails before** (no event). Mutants: emit on failure branch too; `confidence` constant; digest of `""`; `source_refs` empty.
- EXTRACTION mixed hybrid: `llm_calls > 0`, three entities persisted, **two** judged events (LLM-origin only); mutant gating on `result.llm_calls` → three events, test fails.
- EXTRACTION: pre-bound `entity_id` emits nothing; `status != CommandStatus.SUCCESS` emits nothing; sidecar row with missing `model_id` or unprovable correlation → degradation event, no judged emit.
- Enrichment identity-missing: fake LLM with `model=None`, service with no configured default → `EXTRACTION_FAILED`/`model_identity_missing`, no judged event; **fails before** on worker enrich path.
- Fixture: use fake reporting `"test-model-v1"` on success path; `LLMResponse(model=None)` only on the identity-missing case.
- Consolidation: `server.save_memory` with extraction enabled produces the same entity rows + `MUTATION_EXECUTED` count as before (existing MCP tests), and `grep _run_memory_extraction src/` is empty.
- Helper: refactored emitters produce byte-identical payloads to a hand-built `MemoryOpJudgedPayload` (snapshot in test), and a raising `event_log.emit` does not propagate.
- Fixture shapes to avoid: one candidate; two candidates with equal confidence/type; `LLMResponse(model=None)` on every call (masks the identity-missing branch).

Post-deploy (operator): `MEMORY_OP_JUDGED` counts by `op_type` and `source` over a window — EXTRACTION stays 0 until `TRELLIS_ENABLE_MEMORY_EXTRACTION` is set (state this in the PR so a zero is not read as a defect), CLASSIFICATION splits into `classify.shadow` vs `worker:enrich`.

## Non-goals

- **CURATION emitter:** no judged op exists; leave the enum member (removing it is a schema change with no gain).
- Miner: not a memory op; no emitter.
- DISTILLATION discard verdicts: discarded candidates are never constructed, so there is no per-item verdict to log; unchanged.
- The label half (`pack_observations` join) and the trellis-evals exporter — other repo / other issue.
- Any change to what `content_tags` / entity rows contain (including new persisted `extractor_tier` or other property stamps for judged-op correlation).

## Risks the gate will probe

- "Every judged persisting path emits" is only as strong as the scan predicate: a site calling `generate` through a bound-method alias or `**kw` is invisible/unclassifiable — the synthetic tree must show `**kw` *fails* the rule rather than passes silently.
- The digest for `worker enrich`: hashing the re-read content instead of the judged snapshot would be a wrong training input; the test should use a doc whose content changes between snapshot and write and assert the hash is of the snapshot.
- `confidence=0.0` for a null `class_confidence` is a semantic choice; state it in the docstring and PR, do not let it look like a measurement.
- Zip alignment between drafts and `CommandResult`s after `_apply_confidence_gate` — pin with a test that passes `min_confidence` at the seam (even though production does not) so the alignment is by command shape, not index.
- The hybrid `_merge` dedups by `(entity_type, entity_id or name)`; a fresh mint that collides with a deterministic draft is dropped pre-batch — no event, correct, but a reviewer will ask; add a case.
- Consolidation touches `save_memory`, the flagship capture surface: run `tests/unit/mcp/test_capture_surface_roster.py` and the full MCP suite; the `MUTATION_EXECUTED` source of `_run_memory_extraction` referenced by `capture_health.py` docs must be re-pointed.

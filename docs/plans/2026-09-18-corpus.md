## 3. Lane K — the graph observes its own shape (09-12 §4, Phase 3 prerequisites)

Phase 3 needs three things before its first actuator:

- a sensor with base rates (§4.4);
- a stop the tuner cannot move (§5.3);
- producers that no longer create the defects an actuator would clean (#594 §6).

This lane builds those three, then designs the federation map's missing key. No
actuator ships here. Moving one to Tier 1 is a ladder amendment, and that amendment
is the owner's call (§5).

**K1 · `save_knowledge` stops minting orphans on a legacy type.**

- **Measure first**, read-only on prod, for the `gotcha`, `concept` and `system` nodes:
  - which property keys they carry;
  - whether any value names an existing node's deterministic id (the `tool:`,
    `artifact:`, `domain:` … scheme #577 resolves);
  - how many carry `evidence_ref`;
  - how often `relates_to` was passed (`link.create` against `entity.create` for
    `requested_by = mcp:save_knowledge`).

    the alias fits what agents actually write;

    `get_subgraph(depth=0)` read as #577 does. The fix never mints a target.

  `git merge-tree`-checked against #558, #569, #573, #585, #587 and #592.

  exists, and the probe numbers are in §7.

**K2 · Graph-shape sensor: `trellis analyze graph-shape --format json`.**

**The canonical half is refuted, so it is not built.** On prod, `Concept` nodes are domain
hubs and `concept` nodes are notes. They are two populations, not one type spelled two
ways. `well_known.py` aliases `concept` to `Concept`, so canonicalizing on write would
give new notes the hubs' type and merge the two populations. K1's "landing canonical"
Done-when is therefore recorded as refuted, not as met.

**Built.**

- `extract/referents.py` resolves a value to an existing node in this order:
  1. an exact id;
  2. the id each namespace mints from a name. That is the slug for `domain`, `team`,
     `agent` and `tool`, the legacy verbatim tool form after the slug, and the verbatim
     form for `artifact`;
  3. a live name alias.

  It costs one `resolve_alias` per distinct key and one `get_nodes_bulk` read, and it
  never mints.
- `mcp/knowledge_links.py`:
  - `relates_to` takes an id or a name. An ambiguous name creates no edge and lists the
    candidates.
  - `properties.domain` links `appliesTo` to an existing `domain:` node only, with
    `derived_from: properties.domain`.
  - There is one edge per (target, kind), and a note never links to itself.
- `server.py` changes by +22 / −32: the inline `relates_to` block moves out.

**Deviations from the K1 text.**

1. The canonical half was not built, because the probe refuted it (above).
2. It uses `get_nodes_bulk`, not `get_subgraph(depth=0)`. Both are one read, and the
   resolver needs node rows, not a subgraph.
3. It adds the legacy verbatim `tool:` form, which 90 prod ids use. The slug is tried

4. It excludes the note itself. #530 binds a new node's own name alias to that node, so

**Findings for other work.**

- **#577 misses slugged ids.** Its `NamespaceSeedExtractor` builds
  `namespace:normalize_entity_name(token)`. That is the name key, not the slug the trace
  path mints. On prod the name key reaches 506 of 1,219 ids and the minting rules reach
  1,129. The fix is to adopt `referents.namespace_candidates`, judged by replaying
  #577's 85 intents (51 are seeded today).
- **Edge counts cannot see a duplicate `link.create`.** SQLite `upsert_edge` closes the
  current edge with the same (source, target, type) and inserts a new version. The count
  holds while the properties are replaced. Two dedupe mutants survived a count assertion.
  They die on the edge's properties and on the number of `link.create` events.
- **The first self-link test was vacuous.** The fixture's name had an exact-name twin, so
  #530 bound no alias and there was nothing to exclude. The fixture was renamed, and a
  precondition now asserts that the alias is bound.

## Why only one of four is autonomous

`src/trellis_workers/code_authoring/issue_selector.py` is conjunctive and fail-closed: an
issue is a candidate only if it is open, carries **both** `mechanical` and `ready`, carries
none of `keystone` / `owner-only` / `blocked:*`, **and** contains a fenced
```` ```files_allowed ```` block that survives `validate_allowlist`. An absent or invalid
allowlist collapses to `()` and is read as "not a candidate", never as "allow everything".
`select_candidate` then takes **one** issue per cycle, `min(len(files_allowed), number)` —
smallest scope first.

Plans 2 and 3 edit files outside `ronsse/trellis-ai`, which the worker cannot reach at all.
Plan 1 rebuilds production containers and rewrites branch state — neither is undone by
`git revert`, which is the authority bound in `~/.claude/CLAUDE.md`. Plan 4 Part A is a
pure, revertible code change with a bounded allowlist, so it is the one the loop can take.

## 3. Lane B — capability (continues the 09-12 plan)

**B1 · Outcome join (Phase 1.2).** This is the plan's actual deliverable.

- New reader `trellis.learning.judged_outcomes` joins `memory_op.judged` →
  `subject_ref.ref_id` → servings (`PACK_ASSEMBLED.injected_items[]`, chunk ids resolved
  to parents) → citations (`FEEDBACK_RECORDED`).
- Per `op_type × decision` it reports judged, served, cited helpful, cited unhelpful and
  never served, plus the **Phase 1 gate number**: joined, graded rows per 30 days, where
  the gate is > 500.
- Surface: `trellis analyze judged-outcomes --format json`. Read-only.
- **Done when** it is tested and the gate number is measured on a copy of prod.
- **Refutes Phase 1** if that number is far below 500. In that case, say so and don't
  build the exporter.

**B2 · Tiered LLM routing.**

- `llm.tiers.<tier>` sub-blocks inherit from `llm:` the same way `llm.embedding` does.
- `llm.routes.<consumer>: <tier>` assigns each of the six call sites to a tier.
- An unrouted consumer gets the parent block, so an unchanged config builds identical
  clients (pinned by a test). `TRELLIS_RECONCILE_MODEL` keeps its precedence.
- Owner: pointing prod's heavy consumers at litellm `deep` (Kimi) is spend.

**B3 · Outcome backfill.**

- Without it, the tuner's 30-day window starts empty when the Phase 0 stack deploys,
  and Phase 0's gate waits a month.
- `trellis admin backfill-outcomes` replays past `FEEDBACK_RECORDED` × `PACK_ASSEMBLED`
  through the stack's own bridge. It is dry-run by default and idempotent. Stacked on #563.
- **Done when** a dry-run on a prod copy reproduces #563's cell population and
  `RuleTuner` emits at least one proposal. That answers Phase 0's gate offline.
- Owner: `--apply` on prod.

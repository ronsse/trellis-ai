# #369 — Name-alias index completeness: mint at the governed write, backfill once

**Defect:** the name resolver's bootstrap scan is `GraphStore.query(limit=scan_limit)` = the `scan_limit` *newest* current nodes, so once the graph exceeds `DEFAULT_NAME_SCAN_LIMIT` (2000) every not-yet-indexed older entity is unreachable by name for every mention, forever — the miss goes to the LLM residue, which mints a fresh-ULID twin with no name dedupe.

## Verified premise (main-ref f9ff32c)
- `src/trellis/extract/entity_resolution.py:145` `DEFAULT_NAME_SCAN_LIMIT = 2000`; `_scan_for_name` (`:270-305`) calls `graph_store.query(limit=scan_limit)`, `truncated = len(nodes) >= scan_limit`, warns `entity_resolution_scan_truncated`, returns `_ScanResult(matches, mintable=not truncated and len(matches)==1)`. A truncated single hit is still *returned* (used for the edge, not minted). Docstring at `:145` already records the cliff and refuses "raise the cap".
- `query` is `ORDER BY created_at DESC LIMIT n` on every backend: `stores/sqlite/graph.py:1234`, `postgres/graph.py:1164`, `bolt_opencypher/graph.py:1067`. No offset/pagination on the ABC (`stores/base/graph.py`).
- The wrong-answer mechanism runs one step further than the issue states: `alias_match.py:286-313` puts an unresolved mention into `unparsed_residue`; `hybrid.py` fires the LLM whenever residue is non-None; `extract/commands.py:48-130` forwards LLM drafts as `ENTITY_CREATE` with no `entity_id`; `mutate/handlers.py:280-323` `EntityCreateHandler` assigns a ULID and **never checks for an existing node of the same name**. So past the cap, "not found within scan" is not merely a lost `mentions` edge — it is a duplicate entity per mention. The brief's suggested fix ("fail toward not-resolving") is what the code already does; the defect class is *index incompleteness*, and the write path is the only place that sees every named node.
- Existing tests already pin today's behaviour: `tests/unit/extract/test_entity_resolution.py:315-360` (miss past cap warns, single hit past cap warns, truncated does not mint) and `:229-250` (`test_a_later_same_named_entity_does_not_reopen_the_ambiguity` — **first-wins is an already-accepted, pinned decision**).
- Resolver callers: `extract/memory_ingest_hook.py:198`, `mcp/server.py:474`. Both behind `TRELLIS_ENABLE_MEMORY_EXTRACTION` (default off) — the path is dark on the reference deployment, so the fix cannot be measured there; the count "964 nodes on 2026-08-27" is production data, not re-derivable.
- `query(properties={"name": …})` exact-eq is contract-covered (`graph_store_contract.py:178 test_query_filters_by_scalar_property_eq`).

## The change
**Seam 1 — `entity_resolution.py`: `bind_name_alias(graph_store, *, entity_id, name) -> str` (returns `bound|already_bound|kept_existing|contested|skipped`).** Never raises (same soft posture as `_mint_alias`). Rule:
1. `key = normalize_entity_name(name)`; empty → `skipped`.
2. `row = resolve_alias(NAME_ALIAS_SOURCE_SYSTEM, key)`. Bound to `entity_id` → `already_bound`. Bound to another node that `_binding_is_live` → `kept_existing` + `logger.warning("entity_resolution_name_alias_kept_existing", ...)` — this *is* the pinned first-wins rule, applied at write time instead of at first resolve.
3. Key unbound (or stale): `twins = [n for n in query(properties={"name": name}, limit=2) if n["node_id"] != entity_id]`. Any → `contested`, do **not** bind, warn. This is what stops a write from overriding a backfill that refused an ambiguous name (the 7-`hermes` production shape): without it the 8th `hermes` would be bound and shadow seven unbound twins. Exact-raw-name only; case-variant twins remain the already-accepted blind spot.
4. Else `_mint_alias` (existing helper) → `bound`.
Call it from `EntityCreateHandler.handle` after `upsert_node` (`handlers.py:303`) and from `EntityUpdateHandler.handle` when `"name" in command.args` and it changed (`handlers.py:~397`; the old key's binding goes stale and `_binding_is_live` already drops it — no unbind API needed, none added). Both direct `upsert_alias` writes, matching the module's recorded governance note ("no alias verb exists in the pipeline").

**Seam 2 — bounded backfill, same module: `backfill_name_aliases(graph_store, *, max_nodes) -> BackfillReport(bound, already_bound, contested_keys, skipped, truncated)`.** Reads `query(limit=max_nodes + 1)` (the migrator's bounded pattern, `migrate/graph_migrator.py:282-286`), groups by normalized key, binds unique keys via `bind_name_alias`, reports duplicated keys as `contested` (count + keys) and sets `truncated=True` when `len(nodes) > max_nodes` — a truncated backfill must **refuse to bind anything** (it cannot prove uniqueness) and exit non-zero. CLI: `trellis admin backfill-name-aliases [--max-nodes N (default: count_nodes()+1)] [--format json]`; exit below the format branch, `status` derived from the same flag (`tests/unit/test_format_exit_parity_rule.py` scans it). Idempotent: a second run reports all `already_bound`.

## Tests
- **Fails before, passes after:** create 5 entities through `MutationExecutor`+`EntityCreateHandler` (mixed names, mixed casing), resolver with `scan_limit=3`; `resolve("@" + oldest_name.upper())` → `[oldest_id]` and `spy.query_calls == 0` (index hit, no scan). Before: `[]` + truncation warning. Population must be larger than the cap and the target must be the **oldest** (a newest target is in-window and passes on main).
- Rename via `EntityUpdateHandler`: new name resolves past the cap; old name → `[]` (stale binding dropped, scan miss).
- Twin rule: two same-named creates → first resolves (`kept_existing` on the second, warning logged); contested: two unbound same-named nodes written via `upsert_node` directly (structural writers bypass the handler) then a third through the handler → no binding, resolver still refuses (`len == 2` in-window). Kills "bind unconditionally" and "rebind to newest".
- Backfill: graph of 6 nodes — 3 unique names (mixed case), 2 sharing a name, 1 blank name — assert `bound == 3`, `contested_keys == [key]`, `skipped == 1`; then resolver with `scan_limit=1` resolves each unique name and refuses the shared one. Truncated backfill (`max_nodes=2`) binds 0 and reports `truncated`. Second run: `already_bound == 3`. CLI: JSON payload + exit code equal on both formats.
- Soft failure: `resolve_alias` raising inside `bind_name_alias` must not fail the `ENTITY_CREATE` (monkeypatch; assert node written, event emitted, warning logged).
- Keep every existing test in `test_entity_resolution.py` green; `test_a_later_same_named_entity_does_not_reopen_the_ambiguity` uses `_add_entity` (direct `upsert_node`), so it still exercises the resolve-time path — leave it.

## Measurement
Repo-only: mutation report per rule branch. On production the resolver path is dark, so the only honest live number is the backfill report itself (`bound / contested / skipped` counts — counts only, no names in the PR).

## Non-goals
No change to `scan_limit`, `_scan_for_name`, or the LLM-residue dedupe (a residue-side name check would be a second resolver; the index fix makes the residue not fire for known names). No alias verb added to the pipeline. No case-variant twin detection. No `mentions`-edge repair for existing duplicates (curation, separate).

## Risks the gate will probe
- Twin check on `name` raw vs normalized: the exact-eq query cannot see `Hermes`/`hermes`; docstring must say so rather than claim uniqueness.
- The backfill binding on a *truncated* read (silent partial index) — pinned by the `max_nodes=2` test.
- `EntityCreateHandler` upsert of an existing id with a *new* name (it is an upsert): treat like rename — bind the new key. Test it; a create-only hook misses it.
- Handler test fixture with one entity (population of 1) would pass on main; the cap test needs ≥ `scan_limit + 1` nodes and a mixed-name population.
- `bind_name_alias` return value must be asserted per branch, not just "no exception".

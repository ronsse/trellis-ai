# #439 — Withholding note on the REST/SDK pack surfaces (one renderer, every surface)

**Defect:** `POST /packs` and `POST /packs/sectioned` drop `Pack.metadata["withholding"]` on the wire, so no SDK consumer can render #404's note, and `ContextInjector.for_intent` / `skills.get_context_for_task` reproduce the exact "empty == greenfield" failure #404 fixed on MCP/CLI.

## Verified premise (main-ref f9ff32c)
- `src/trellis/retrieve/pack_builder.py:828-846` (flat) and `:1153-1168` (sectioned) stamp `metadata={"withholding": summarize_withheld(...).as_telemetry()}` on the pack object. Keys: `total, by_reason, withheld_item_ids, non_absence_reasons, section_filtered, served_count`.
- `src/trellis_wire/dtos.py:119-129` `PackResponse` and `:152-161` `SectionedPackResponse` carry **no** `metadata`/`withholding` field. `SectionedPackResponse` has no top-level `retrieval_report` either; per-section `retrieval_report.rejected_items` (`pack_builder.py:~1124`) carries content-floor rejections only — never `noise`/`archived`/`section_filtered`.
- `src/trellis_api/routes/retrieve.py:105-136` `assemble_pack` returns `retrieval_report=pack.retrieval_report.model_dump()`; `:139-176` `assemble_sectioned_pack` returns `sections=[s.model_dump(mode="json")]`. Neither reads `pack.metadata`.
- `src/trellis_sdk/hooks.py:139-174` `for_intent`: `if not items: return ""`. `:176-222` `for_entities` → `_entity_fallback` → `""`. `src/trellis_sdk/skills.py:20-42` → `f"No relevant context found for: {intent}"`. `src/trellis_sdk/_format.py` formatters have no withholding argument.
- MCP (`src/trellis/mcp/server.py:919-952, 1017-1024`) and CLI (`src/trellis_cli/retrieve.py:143-173,195`) render via `withholding_from_payload` + `format_withholding_note`; CLI JSON arm already ships the payload **verbatim, ids included**, with a comment that ids already ride `rejected_items` on `POST /packs`.
- Isolation: `tests/unit/sdk/test_isolation.py` forbids `trellis.*` imports in `trellis_sdk`; `tests/unit/wire/test_parity.py:95-107` forbids `trellis.*` in `trellis_wire`. Core already imports `trellis_wire` (`src/trellis/wire/translate.py:20`), and `trellis_sdk` already imports `trellis_wire` (`client.py:33`). structlog is a hard dep of the single distribution, so `trellis_wire` may import it.
- Caller's note pointed at `routes/packs.py` and `trellis/hooks.py` — neither exists; the real files are above.

## The change (three parts, one PR)
**1. Wire.** In `trellis_wire/dtos.py` add `withholding: dict[str, Any] | None = None` to both `PackResponse` and `SectionedPackResponse` (docstring: the `Pack.metadata["withholding"]` telemetry, verbatim; `None` only from a server older than API 1.2). Populate in both routes from `pack.metadata.get("withholding")`. Regenerate `docs/api/v1.yaml` (`make openapi-check`). Bump `API_MINOR` 1→2 in `src/trellis/api_version.py` with the dated comment; `tests/unit/api/test_version.py` reads the constant so it needs no edit. **Exposure note for the PR body:** on the flat route the ids are already on the wire under `retrieval_report.rejected_items`, so no new exposure class; on the sectioned route `withheld_item_ids` is new on the wire — same read-scope as the items, same posture the CLI JSON arm took (`retrieve.py:143-173` comment). If the gate objects, strip `withheld_item_ids` on the sectioned response only; do not invent a second payload shape.

**2. One renderer, importable by the SDK.** Move the *pure* half of `src/trellis/retrieve/withholding.py` — `WithheldGroup`, `WithholdingSummary` (incl. `total`, `section_note_applies`, `as_telemetry`), `withholding_from_payload`, `format_withholding_note`, `_count`, `_keys`, `_str_list` — into new `src/trellis_wire/withholding.py`. Keep `summarize_withheld`, `NON_ABSENCE_REASONS`, `SECTION_FILTER_REASON` in core (they read `RejectedItem`), and have `trellis/retrieve/withholding.py` re-export the moved names so every existing import (`mcp/server.py`, `trellis_cli/retrieve.py`, tests) is untouched. Pin with `assert trellis.retrieve.withholding.format_withholding_note is trellis_wire.withholding.format_withholding_note` (and the same for `withholding_from_payload`) — that identity is what "one renderer" means; a duplicate in `_format.py` would satisfy the fixture-parity pattern but is the drift shape the issue names. Rejected alternative: duplicating the ~25-line note in `_format.py` with a parity fixture.

**3. SDK.** `_format.py`: add `withholding: WithholdingSummary | None = None` kwarg to `format_pack_as_markdown` and `format_sectioned_pack_as_markdown`; render `format_withholding_note(withholding)` in the header **above the first item block**, exactly as the MCP formatter does (the item loop breaks on budget, so an appended note prints only for packs that fit — #404's recorded trap). Thread `withholding_from_payload(pack.get("withholding"))`: `skills.get_context_for_task` (empty → existing sentence + note when note non-empty); `hooks.for_intent` (empty → return the note if any, else `""`; non-empty → pass to formatter); `hooks.for_entities` (fallback first; if the fallback is also empty → note or `""`); `client.get_objective_context` / `get_task_context` and the `async_client.py` twins (`:253,325,362`) → pass `withholding=` to the sectioned formatter. Section note still renders only when `served_count == 0` — that logic lives in the moved `section_note_applies`, so no SDK copy of the rule.

# #514 — One JSON-response parser for the five LLM prompt sites; make the distill malformed outcome countable

**Defect (one sentence):** five call sites each hand-roll a *different* markdown-fence stripper + `json.loads` over LLM output (one of them buggy), and on the one site that feeds the nightly capture loop a malformed judge response is folded into "judged, nothing worthy" — the session is watermarked away and no counter can ever see it.

## Verified premise (main-ref = f9ff32c)

All five `.generate(messages=...)` sites in `src/` (exactly five; hand-read):

Providers each site runs against: all five go through `LLMClient.generate` (`src/trellis/llm/protocol.py`), so every site can meet `OpenAIClient` (which the reference deployment points at **Ollama**'s `/v1`) *or* `AnthropicClient`. Neither adapter offers a JSON mode today (`providers/openai.py` sends temperature/max_tokens only; `providers/anthropic.py` sends model/messages/max_tokens/system — #517). `AnthropicClient` has no structured-output path at all, and Ollama's OpenAI-compat layer has no Anthropic analogue — so a protocol-level `response_schema` would be a three-way capability matrix, not a flag. Not needed to remove this defect class.

Existing tests that pin current per-site behaviour (must keep passing): `tests/unit/mcp/test_reconcile.py::TestParseVerdict` (`test_fenced_code_block`, `test_malformed_returns_none` params), `tests/unit/workers/session_capture/test_distill.py::test_parse_candidates_tolerates_code_fence` / `_malformed_returns_empty`, `tests/unit/workers/enrichment/test_service.py::test_json_in_code_fence` (+ the inner-except test near :479), `tests/unit/classify/test_llm_classifier.py`.

"Measure before building" — the malformed *rate* cannot be derived from the repo; it needs the production event log (`EXTRACTION_FAILED` rows with `failure_kind=parse_error`, plus reconcile fallback markers). Sites 3 and 2 emit nothing countable today, which is why this plan makes the count *possible* rather than reporting one.

## The change

### A. One seam: `src/trellis/llm/json_response.py` (new; `trellis` is a dependency of both worker packages)

```python

```

Sites keep their **own** fallback semantics (that is the part that is genuinely per-site) and only replace the strip+loads(+salvage) block:
- llm.py: `_parse_json_with_exception` calls `parse_json_response`, keeps the bare-list lift and `(None, exc)` contract; delete `_CODE_FENCE_RE`.
- reconcile.py: `parse_verdict` → `parse_json_response` in a try; `None` on `JSONResponseError`. Salvage is *new* here (a preamble before the object now parses); validation after parse is unchanged so the strictness tests still hold.
- distill.py: `parse_candidates` → see B.
- miner.py: replace `lines[1:-1]` with the seam. This fixes the latent last-line bug.
- enrichment/service.py: replace strip + regex salvage with the seam; keep the `emit_extraction_failure` branch reading `type(exc).__name__` from `JSONResponseError.__cause__` or the error's own class.

### B. Make the distill malformed outcome observable (the capture-loop half)

`parse_candidates` returns `list[CandidateMemory] | None` — `None` = "could not parse a JSON array" (was `[]`). `distill_session` propagates it as a *third* outcome distinct from unreachable. Smallest caller change in `capture.py:322-330`:

```python
if candidates is None: report.sessions_judge_unavailable += 1; return  # unchanged
if candidates is MALFORMED (sentinel or a small enum DistillOutcome): report.sessions_judge_malformed += 1; log warning "distill_response_malformed"; fall through to the existing empty-candidates path (watermark advances)
```
Prefer a tiny `DistillOutcome` enum/dataclass over a sentinel if the coder finds the `None`/`[]`/sentinel triple unreadable — but do **not** change watermark behaviour (see non-goals). Add `sessions_judge_malformed: int = 0` to `CaptureReport` (`models.py:175`), to its `to_payload` dict (:261 area) so it rides `CAPTURE_SWEEP_COMPLETED`, and to `ops/capture_coverage.py`'s funnel + the two note-rendering branches (:217-226, :360) using the `sessions_skipped_empty` sentence shape. Note in the docstring that a malformed *judge* is not `malformed_lines` (transcript lines).

### C. Derived rule pinning the seam (house standard 4)

`tests/unit/llm/test_json_response_rule.py`: AST-scan `src/` for `Call` nodes whose func is `Attribute(attr="generate")` carrying a `messages=` keyword (helper `generate_call_sites(tree) -> list[(path, lineno)]` added to `tests/ast_rules.py`; #264's plan reuses it). For every module containing one, require the module to reference `parse_json_response` (import-name check via `construction_names`/`calls_to_any`) **or** be listed in `NOT_JSON_SITES` with a reason (today: empty). Guards: `assert_hand_read_floor(found, 5)`; decoy check — `AdvisoryGenerator.generate(days=...)` call sites (`retrieve/advisory_generator.py`, `trellis_api/routes/admin.py:313`, `trellis_cli/analyze.py:1325`, `trellis_cli/worker.py:772`) must NOT be collected (`messages=` keyword is the discriminator, not the attr name); synthetic tree via `assert_scan_is_not_vacuous` containing (a) `await self._llm.generate(messages=m)` (caught), (b) `gen = client.generate; gen(messages=m)` (bound-method evasion — document as a known blind spot rather than claim it is caught, or catch `Name("generate")` calls with `messages=` too), (c) `client.generate(**kw)` (flag as "cannot classify" → fail, the #424 `**kwargs` treatment), (d) a decoy `x.generate(days=3)` (must not be caught), (e) a module with a site and no parser import (must fail the rule).

## Tests (fail before / pass after) and mutants

- `test_strip_code_fence_keeps_last_json_line_when_trailing_fence_missing` — input ```` ```json\n[{"a":1},\n{"b":2}] ```` (no closing fence). **Fails on old miner logic**; port the same input into `tests/unit/workers/learning/test_miner.py` driving `_parse_candidates` end-to-end (population 2 items, distinct titles/confidences, so a dropped line changes the count).
- `test_parse_json_response_salvages_preamble` (`"Sure! {…}"` and `"Here you go:\n[…]"`) — kills `salvage=False` default mutant and a `find("{")`-only mutant (array case).
- Reconcile: parametrize existing `TestParseVerdict` with a preamble-wrapped valid verdict → now `(ADD, 0.9)` not `None`; keep every existing malformed param green (kills "salvage swallowed validation").
- Distill: `test_parse_candidates_malformed_is_distinct_from_empty` — `"not json"` → `None`, `"[]"` → `[]`; and a `capture.py` sweep test with a fake client returning `"garbage"` for session A and `"[]"` for session B (population 2, mixed) asserting `sessions_judge_malformed == 1`, `sessions_triggered == 2`, `sessions_judge_unavailable == 0`, both watermarked, and the field present in the emitted `CAPTURE_SWEEP_COMPLETED` payload. Kills: counter never incremented, counter folded into unavailable, field omitted from `to_payload`.
- `capture_coverage` note test: funnel with `sessions_judge_malformed=2` renders the sentence; with 0 it does not (both branches, so a constant sentence fails).
- Rule test: the synthetic-tree cases above; plus the rule fails on a copy of the tree with the parser import removed from one site.
- Mutation targets to report: `strip_code_fence` dropping the "one trailing line" guard; `parse_json_response` swapping `rfind` → `find`; sentinel/None confusion in `distill_session`; `to_payload` key.

Fixture shapes to avoid: single-candidate arrays (a dropped line then reads as "empty", same as malformed); all-identical confidences; a sweep fixture with one session.

On production (operator, not this PR): `trellis analyze health` funnel now shows `sessions_judge_malformed` per sweep; `EXTRACTION_FAILED` with `failure_kind=parse_error` by `extractor_id` gives the other three sites' rates. ## Non-goals (say so in the PR)

- Structured outputs / `response_schema` on `LLMClient`: provider matrix is OpenAI json_object vs Ollama `format` vs Anthropic tool-use; defer until the malformed rate is measured (the issue's own ordering).
- Retrying a malformed distill (leaving the session un-watermarked): at `temperature=0.0` a retry likely reproduces the same output and would pin the session forever; the semantic call (retry vs count) is an owner question only if the measured count is non-trivial.
- Changing any site's post-parse validation or fallback event vocabulary.
- Touching `providers/*` (#517 just did).

## Risks the gate will probe

- "One seam" claim: reviewer greps for a residual `startswith("```")` — there must be zero in `src/`.
- Salvage on reconcile/distill widens acceptance; a reviewer will ask for a case where salvage recovers a *wrong* object (e.g. two objects in a reply — first `{`..last `}` spans both and fails to parse → still `JSONResponseError`, good; document it).
- Docstring of `parse_candidates` currently says "fail-closed" — must be rewritten to say malformed is `None`, counted, and watermarked.
- The rule's import-presence check is weak (a site could import and not call). Say so in the test docstring; the roster in #264 is the stronger per-site recipe test.
- `CaptureReport` is `extra="forbid"`-adjacent? It is a dataclass; check any JSON schema/consumer (`capture_coverage`, UI) that enumerates keys.
